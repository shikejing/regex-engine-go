# regex-engine-go

一套自包含、可复用的正则匹配能力，适用于日志过滤、路由匹配与文本校验等场景。
编译与匹配完全在本仓库内实现，**不依赖** 标准库 `regexp` 或任何第三方正则引擎
（标准库 `regexp` 仅在测试中作为参照出现）。

## 快速开始

```go
re, err := regex.Compile(`(\w+)@(\w+)\.com`)
if err != nil {
    // err 是 *regex.SyntaxError，携带出错位置（字节偏移）
    log.Fatal(err)
}
ok, _ := re.Match("contact alice@example.com") // true
loc, _ := re.Find("contact alice@example.com") // [8 27]
slots, _ := re.FindSubmatch("contact alice@example.com")
// slots = [8 27  8 13  14 21]：整体匹配 + 各捕获组的字节区间
```

`Compile` 的产物 `*Regexp` **不可变**，匹配过程不修改任何共享状态，
同一实例可被任意多个协程并发安全地使用（见 `TestConcurrentUse`）。

## 语法子集

| 语法 | 说明 |
|---|---|
| `a`、`é` | 字面量（按 Unicode rune 匹配） |
| `\n \t \r \f \v`、`\xHH`、`\uHHHH` | 转义 |
| `\.` `\*` `\+` `\?` `\(` `\)` `\[` `\]` `\{` `\}` `\|` `\^` `\$` `\\` `\/` `\-` | 标点转义为字面量 |
| `\d \D \w \W \s \S` | 预定义字符类（ASCII 口径）及其取反 |
| `[abc]` `[a-z]` `[^a-z]` `[\d.]` | 字符类、区间、取反、类内嵌预定义类 |
| `.` | 任意字符，**不含换行** `\n` |
| `^` `$` | **文本**起始 / 结束锚点（不是行锚点） |
| `*` `+` `?` | 量词（贪婪），后缀 `?` 变懒惰，如 `*?` |
| `{n}` `{n,}` `{n,m}` | 计数量词，`n,m ≤ 1000`，同样支持懒惰形式 |
| `a|b|c` | 选择分支 |
| `(...)` | 捕获分组，按左括号顺序从 1 编号 |
| `(?:...)` | 非捕获分组 |
| `\1` … `\9` | 反向引用（见下文「两类模式」） |

明确**不支持**并在编译期报错：行锚点修饰 `(?m)`、内联标志 `(?i)`、
命名分组、环视、`\b` 等零宽断言、`\0`、八进制转义、未知字母转义（如 `\q`）。
所有语法错误都返回 `*SyntaxError`，`Pos` 字段为出错位置的字节偏移，
错误消息形如 `regex syntax error at offset 2: missing closing ')'`。

其他边界约定：

- 量词允许叠加（`a**` 等价于 `(a*)*`），与 RE2 一致；
- 单独的 `{` 若不是合法计数形式则按字面量处理（`a{` 报错，`{` 单独出现是字面量）；
- 空模式合法，在位置 0 匹配空串；空分支 `a(|b)c` 合法；
- 编译产物指令数上限 100000，超出时 `Compile` 报错，防止 `{n,m}` 展开失控。

## 匹配语义（确定性保证）

同一模式与同一输入，在任何一次运行中都给出**完全一致**的结果：

1. **最左匹配**：未加锚点的搜索返回起始位置最小的匹配；
   起点相同时按下述优先级规则决出唯一结果。
2. **分支优先级**：选择分支按**书写顺序**优先（`a|ab` 在 `"ab"` 上匹配 `"a"`），
   与 Perl / RE2 的 leftmost-first 语义一致，不是 POSIX 最长匹配。
3. **量词**：贪婪量词优先多匹配，懒惰量词优先少匹配；
   嵌套结构中外层优先（与 Perl / RE2 一致）。
4. **捕获边界**：捕获组边界由上述优先级唯一确定；
   未参与匹配的组报告为 `[-1, -1]`；重复中的捕获组记录**最后一次**迭代的边界。
5. 反向引用 `\N` 若指向未参与的组，按匹配空串处理。

`FindSubmatch` 返回的槽位布局为 `[m0s, m0e, g1s, g1e, ...]`，均为字节偏移。

## 执行代价模型

引擎按模式是否含反向引用分为两类，行为边界清晰：

### 普通模式（无 `\1`…`\9`）：Pike VM，线性保证

- 使用 Thompson NFA 模拟（Pike VM），所有候选起点作为并发线程同步推进；
- 时间复杂度 **O(len(input) × len(prog))**，随输入规模**线性**增长，
  不存在指数回溯，病态模式（如 `(a*)*b`）也不会失控；
- 未加锚点的搜索**不会**退化为逐起点重扫的平方级开销——
  新起点以最低优先级注入线程列表，每个输入位置只被扫描一次；
- 内存占用 **O(len(prog) × (捕获组数+1))**，与输入长度无关，
  输入按 rune 流式读取，**不整体复制**，可承受远超模式长度的大输入。

### 含反向引用的模式：有界回溯

- 反向引用无法用 NFA 模拟表达，此类模式切换到带回溯的执行引擎；
- 语义与 Pike VM 完全一致（最左、分支按书写顺序、贪婪/懒惰相同）；
- 引擎设有**步数预算**（默认 1,000,000 条指令，所有候选起点共享），
  预算同时限制了递归深度，时间与内存都有界；
- 执行代价超过预算时，匹配以 `ErrBacktrackLimit` **可区分地终止**
  （`errors.Is(err, regex.ErrBacktrackLimit)`），不会卡死，也不会返回错误结果；
- 空循环（如 `(a*)*` 的零宽迭代）在回溯中被确定性地切断，
  不会导致预算被无意义耗尽。

> 注意：反向引用的线性保证**不**覆盖——这正是第 6 条要求的边界：
> 普通模式的线性代价不受反引用支持的影响，两类模式在编译期即分流。

## API 一览

```go
func Compile(src string) (*Regexp, error)   // 编译，语法错误返回 *SyntaxError
func MustCompile(src string) *Regexp        // 出错时 panic
func (re *Regexp) String() string
func (re *Regexp) NumSubexp() int
func (re *Regexp) Match(input string) (bool, error)
func (re *Regexp) Find(input string) ([]int, error)        // 最左匹配区间 [s, e)
func (re *Regexp) FindSubmatch(input string) ([]int, error) // 整体 + 捕获组区间
```

所有匹配方法：未匹配返回 `nil` / `false`；触发回溯预算时返回
`ErrBacktrackLimit`（`Match` 也会返回该错误，与"无匹配"严格区分，
不会把预算终止静默吞掉变成错误的 false）。
