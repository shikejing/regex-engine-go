# regex-engine-go

一个自包含的 Go 正则表达式引擎，面向日志过滤、路由匹配、文本校验等场景。
模式串的解析、编译与匹配全部在本仓库内实现，**不委托**标准库 `regexp` 或任何第三方正则实现。

## 快速开始

```go
re, err := regex.Compile(`(\w+)@(\w+)\.com`)
if err != nil {
    // 编译期语法错误，err 是 *regex.Error，携带出错位置
    log.Fatal(err)
}
defer ... // 无需释放；编译产物不可变，可安全地被多个 goroutine 共享

m, err := re.FindStringSubmatch("mail alice@example.com")
// m == ["alice@example.com", "alice", "example"]
```

API 一览（所有匹配方法都以 `error` 区分"无匹配"与"代价超限"，见下文）：

| 方法 | 说明 |
|---|---|
| `Compile` / `CompileWithOptions` / `MustCompile` | 编译模式串为可复用的 `*Regexp` |
| `re.MatchString(s)` | 是否存在匹配 |
| `re.FindString(s)` | 最左匹配的文本 |
| `re.FindStringIndex(s)` | 最左匹配的 `[start, end)` 字节区间 |
| `re.FindStringSubmatch(s)` | 整体匹配 + 各捕获组文本 |
| `re.FindStringSubmatchIndex(s)` | 整体匹配 + 各捕获组字节区间（未参与的组为 `[-1,-1]`） |
| `re.NumSubexp()` / `re.String()` | 捕获组数量 / 原始模式串 |

## 语法子集

| 类别 | 语法 |
|---|---|
| 字面量 | 普通字符；`\.` `\\` 等非字母数字转义表示其自身 |
| 转义 | `\n \r \t \f \v \a`、`\xHH`、`\uHHHH`、`\d \D \w \W \s \S` |
| 字符类 | `[abc]`、`[a-z]`、`[^a-z]`、类内转义（`[\d.]`）、`]` 在首位为字面量、`-` 在两端为字面量 |
| 点号 | `.` 匹配除 `\n` 外的任意字符 |
| 锚点 | `^` `$`（行锚点）、`\A` `\z`（文本首尾）、`\b` `\B`（单词边界，`[0-9A-Za-z_]`） |
| 量词 | `*` `+` `?` `{n}` `{n,}` `{n,m}`，均可加 `?` 后缀变为懒惰形式 |
| 选择 | `a|b|c` |
| 分组 | `(...)` 捕获、`(?:...)` 非捕获 |
| 反引用 | `\1` … `\9`（引用对应编号的捕获组已匹配的文本） |

以下写法**不支持**，编译期报错并给出字节偏移（`*regex.Error`）：
`(?i)` 等内联标志、`(?<name>...)` 命名分组、环视（lookahead/lookbehind）、
`\Q...\E`、POSIX 字符类 `[:alpha:]`、嵌套量词（`a**`）、
计数超过 1000 的量词、编译后指令数超过 100 000 的模式。

## 匹配语义（确定性保证）

引擎实现 **最左优先（leftmost-first，Perl/PCRE 风格）** 语义：

1. **最左匹配**：未加锚点的搜索从位置 0 开始尝试，返回起始位置最靠左的匹配；
   起始位置相同的情况下才比较分支优先级。
2. **分支优先级**：选择分支 `a|b` 优先尝试左侧分支；贪婪量词优先"多匹配"，
   懒惰量词优先"少匹配"。整体匹配成功即停止，不回退去尝试"更长的其他分支"。
3. **捕获组边界**：由上述优先级唯一确定。重复分组 `(a|b)+` 的捕获是**最后一次**
   迭代的边界；未参与匹配的组报告为 `[-1,-1]`。
4. **确定性**：同一模式、同一输入，在任何一次运行、任何一个 goroutine 中都给出
   完全一致的匹配结果与分组边界。引擎内部不存在任何随机或时序相关的选择。

同一模式与输入在任何一次运行里结果完全一致；测试中与 Go 标准库
（同为 leftmost-first 语义）做了随机差分对照，并做了 1000 次重复运行的确定性测试。

## 执行代价模型

引擎按模式是否含反引用选择两条执行路径，编译期即确定：

### 普通模式（无反引用）：线性时间

使用 Thompson NFA 模拟（Pike VM）：

- 时间 `O(输入长度 × 编译后指令数)`，对固定模式即**随输入线性增长**；
  不存在指数级回溯，`(a+)+$` 这类"病态模式"也不会退化。
- 未加锚点的搜索在**单趟扫描**内完成：每个位置只是向活跃线程集合注入一个
  新起点线程，不会对每个起始位置重新扫描输入，因此没有平方级开销。
- 内存 `O(指令数 × 捕获槽数)`，有界；匹配直接在输入字符串上进行，
  **不整体复制输入**，可承受远超模式长度的大输入。

### 含反引用模式：有界回溯

反引用无法用 NFA 模拟表达，改用深度优先回溯 VM，语义与 Pike VM 完全一致
（同样的最左优先规则），并带有两条安全边界：

- **步数预算**：单次搜索执行的指令步数有上限（默认 1 000 000，
  可用 `Options{BacktrackLimit: n}` 调整）。预算耗尽时搜索**立即终止**，
  所有匹配方法返回 `regex.ErrBacktrackLimit` —— 与"无匹配"明确区分，
  绝不会卡死，也不会把"算不完"伪装成"不匹配"。
- **空循环保护**：对可能匹配空串的循环体，零进展的迭代会被剪枝，
  `(a*)*\1` 这类模式不会死循环。

代价边界：含反引用的模式不享受线性保证。未加锚点时按起始位置逐个尝试，
每个位置的回溯代价受预算约束；病态模式（如 `(a|aa)+\1$`）会在预算处终止并
返回 `ErrBacktrackLimit`。若输入很大且模式含反引用，应相应调大预算或先切分输入
（例如按行过滤）。

## 并发与不可变性

`*Regexp` 编译完成后完全不可变：程序指令、字符类、配置在编译期定型。
每次匹配调用都新建私有的执行状态（线程表 / 回溯栈 / 捕获槽），
不读写任何共享可变状态，因此同一编译产物可被任意多个 goroutine
并发用于匹配，不同匹配之间互不影响（测试中以 `-race` 验证）。

## 不支持的语法为什么直接报错

凡是本引擎不能**确定性地、有界代价地**执行的写法（环视、内联标志、命名分组等），
一律在编译期拒绝并给出位置，而不是静默改变语义。语法错误类型为：

```go
type Error struct {
    Pos int    // 模式串中的字节偏移
    Msg string // 错误描述
}
```

覆盖：贪婪/懒惰量词与捕获语义、最左匹配、非法模式的编译报错（含位置）、
